### RF-02
Requirement / AC: FR-08 / Terminology and Syntax Discrepancy (Command vs. Option)
File: `REQUIREMENTS.md` (and PR description / Issue #1)
Evidence:
- `REQUIREMENTS.md` specifies: *"The CLI must support a 'help' command that shows command-line options and syntax."*
- PR #2 Description states: *"introduce a --help command to the CLI application."*
- Issue #1 states: *"I want to add a '--help' command that shows all information..."*
- Testing behavior: Executing `python -m src.cli help` fails with `customer_search: error: unrecognized arguments: help` (Exit Code `2`). Executing `python -m src.cli --help` succeeds (Exit Code `0`).
Problem: 
There is a conflicting specification between a subcommand (`help`) and a flag (`--help`). If the requirement strictly mandates a `"help" command` (positional argument), the current CLI implementation fails. If it intended an option/flag (`--help`, `-h`), the requirement text in `REQUIREMENTS.md` is ambiguous and deviates from standard CLI terminology.
Recommended next step: 
Clarify the requirement phrasing in `REQUIREMENTS.md` to specify standard flags (e.g., `FR-08: Help Option — The CLI must support --help and -h flags that show command-line options and syntax.`) or implement subcommand parsing if a positional `help` command is truly desired.
